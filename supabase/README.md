# راه‌اندازی Supabase برای رادمهر

سه گام، حدود ۱۰ دقیقه.

## گام ۱ — ساخت پروژه و اجرای اسکیما

1. برو به [supabase.com/dashboard](https://supabase.com/dashboard) → **New project** (منطقه را نزدیک ایران انتخاب کن؛ مثلاً Frankfurt).
2. از منوی **SQL Editor** فایل [`migrations/0001_init.sql`](./migrations/0001_init.sql) را کپی کن و **Run** بزن.
   - جدول‌ها، سیاست‌های دسترسی (RLS)، تریگر ساخت پروفایل و توابع `create_invite` / `redeem_invite` ساخته می‌شوند.

## گام ۲ — خاموش کردن تأیید ایمیل (مهم)

از آنجا که ورود با **شماره موبایل** است و ایمیل واقعی وجود ندارد:

- **Authentication → Sign In / Providers → Email**: گزینهٔ **Confirm email** را خاموش کن.
- **Authentication → Providers → Phone**: لازم نیست فعال شود.

> اگر می‌خواهی تأیید ایمیل روشن بماند، به‌جای ثبت‌نام سمت‌کلاینت از Edge Function زیر استفاده کن (کاربر را تأییدشده می‌سازد).

## گام ۳ — Edge Function ثبت‌نام (اختیاری ولی توصیه‌شده)

اگر ثبت‌نام عمومی با ایمیل ساختگی را نمی‌پسندی، یا می‌خواهی کاربران بدون تأیید ایمیل ساخته شوند:

```bash
npm i -g supabase
supabase login
supabase link --project-ref <project-ref>
supabase functions deploy phone-signup --no-verify-jwt
```

اپ به‌طور خودکار اول `auth.signUp` را امتحان می‌کند؛ اگر جواب نداد، همین تابع را صدا می‌زند.

## گام ۴ — اتصال اپ

در ریشه‌ی پروژه فایل `.env` بساز:

```env
VITE_SUPABASE_URL=https://xxxxx.supabase.co
VITE_SUPABASE_ANON_KEY=eyJhbGciOi...
```

(از **Project Settings → API** بردار.) بعد `npm run dev` را دوباره اجرا کن. نشان «متصل به Supabase» در هدر اپ ظاهر می‌شود و
داده‌ها به‌جای مرورگر، در دیتابیس ذخیره می‌شوند.

## نگاشت شماره به ایمیل داخلی

Supabase برای ورود با رمز به ایمیل نیاز دارد. ما شماره را قطعی و یکتا نگاشت می‌کنیم و هیچ ایمیلی ارسال نمی‌شود:

```
09121234567  →  9121234567@phone.hamghadam.local
```

این منطق در `src/lib/supabaseClient.ts` تابع `phoneToEmail` است. اگر بعداً SMS OTP خواستی، کافی است یک Edge Function با
کاوه‌نگار/فراز‌اسمس اضافه کنی و همان را جای این مسیر بگذاری.

## نقش‌ها و اتصال‌ها

| نقش | دسترسی |
|---|---|
| مشاور (`counselor`) | ساخت/ویرایش برنامه، تمرین، چک‌این، جلسه و بازخورد برای دانش‌آموزانِ وصل‌شده |
| دانش‌آموز (`student`) | دیدن برنامه، تیک انجام‌شدن، ویرایش (اگر برنامه «قابل ویرایش» باشد)، تأیید یا درخواست اصلاح، چک‌این، گفت‌وگو |
| والد (`parent`) | فقط خواندن: برنامه، پیشرفت، روند حال/مطالعه، خلاصه‌ی جلسه و گفت‌وگو |
| مدیر (`admin`) | دسترسی کامل (برای مرکز چندمشاوره) |

اتصال مشاور و دانش‌آموز از دو راه: (۱) کد دعوت با تابع `redeem_invite`، (۲) افزودن با شماره موبایل از پنل مشاور.

## تست سریع امنیت (RLS)

با دو حساب متفاوت وارد شو و مطمئن شو:
- دانش‌آموزِ A نمی‌تواند برنامه یا چک‌این دانش‌آموزِ B را ببیند.
- والد فقط جدول‌های مربوط به فرزند خودش را می‌بیند و امکان نوشتن روی `plans`/`plan_items` را ندارد.
